# 根据业务设计页面：参考调研与 dimensional-drawing

适用于新业务页面、明显改变信息结构的改版，以及页面规范定义。仅修正文案或局部样式时，不必重新画整页。先明确业务任务，再选布局；技术语言不限制参考项目。

## 1. 先定义页面任务

从需求提取：使用者/角色、业务对象、当前状态、主要任务、必要字段与关联数据、可用操作与权限、入口/返回路径、成功与失败结果。缺少信息时先沿用已确认内容，不为了模板完整而增加模块、报表或操作。

页面设计先读[后台页面推荐标准](page-recommended-standard.md)；组件组合按[共用规则](component-recommended-standard.md)确定槽位、空间和责任。页面标准要求：先写页面契约，再确定布局、滚动与验收样本。它提供基础/分组/分步表单、列表、详情与设置的可执行起点；其中640/960px阅读宽、16/24px间距、两列预算等均为设计推荐，不能标成Core现状或实测，也不要求其他项目存在此文件。

选择页面结构，并说明为什么：

| 业务任务 | 优先考虑的结构 |
| --- | --- |
| 查找、筛选、批量处理对象 | 列表：对象页头 → 查询工具栏 → 结果/选择 → 分页 |
| 少量字段的创建或编辑 | 基础表单：任务页头 → 受控阅读宽度、纵向单列字段 → 操作 |
| 多组相关信息统一提交 | 分组长表单：按业务分组 → 组内相关短字段可并列 → 统一操作 |
| 明确的先后步骤、阶段校验 | 分步表单：进度 → 当前步骤 → 上下步/提交；不要只因字段多就分步 |
| 分类配置、个人或组织设置 | 设置：分类入口 → 当前主题 → 组说明与字段 → 明确保存范围 |
| 查看对象并判断下一步 | 详情：对象/状态/操作 → 只读信息组 → 业务需要的关联明细或记录 |
| 预览、发布摘要等确实独立的信息 | 主区 + 辅助栏；先解释辅助栏用途，再确定固定/比例宽度 |

“两列字段”“左右标签”“主辅两栏”是不同维度。基础表单不默认套商品创建模板；详情不默认画成禁用输入框。长文本、地址、富文本与子表通常应跨整行。页头操作、底部操作和组级保存按提交范围设计，不把所有按钮位置都加一遍。

## 2. 去哪里找参考

先查当前 Forge 的模板、案例和已确认规范；确认业务任务匹配后才继承布局。没有合适结构或需要验证布局时，再找成熟脚手架的官方演示、官方文档截图与设计说明。优先看整页，不只看单个输入框的 API。

| 来源 | 重点找什么 | 入口 |
| --- | --- | --- |
| Forge | 可复用组件、真实 props、已实现的页面骨架 | `scripts/list.mjs`、`scripts/get-case.mjs`、`scripts/get-template.mjs`；本仓 `src/app/templates/`、`src/app/cases/` |
| ShipAny | SaaS 用户设置、管理端配置分类、账户与订阅场景 | https://shipany.ai/docs/shipany-two/ ；在官方文档查 settings/admin、配置与对应演示链接 |
| Ant Design Pro | 基础/高级/分步表单、基础/高级详情、个人设置 | https://preview.pro.ant.design/ ；https://ant.design/docs/spec/research-form/ |
| Vben Admin | 后台表单、描述列表、响应式字段布局、操作区 | https://doc.vben.pro/ ；由文档进入对应演示版本 |
| Filament（PHP/Laravel） | 业务分组、Grid/Section、设置布局、Infolist 详情 | https://filamentphp.com/docs/ ；选定版本后查看 layout、sections、viewing records |

这些是检索入口，不表示所有页面都已验证或当前版本仍在同一路径。访问时确认版本与最终 URL；入口失效就沿官网导航找，不循环猜 URL。可按实际业务补充其他成熟项目，不受 React、Vue、PHP 等语言限制。

浏览器遵守工作区规则，优先复用已运行的 Chrome。公开演示不可访问时使用官方截图/文档，并记录限制；不为研究擅自注册、付费或修改真实配置。

记录每个采用的参考：项目/版本、最终 URL、页面类型、证据方式（实际浏览/官方静态截图/文档说明/未验证）、观察到的区域结构、与本业务相同和不同之处、采用/放弃理由。截图只证明当时可见结构；文档说支持某布局，不证明某实际页面就用了它。登录后的 ShipAny 页面未查看时，不声称测量过它的几何。

## 3. 用 dimensional-drawing 把结构落实为可审阅图纸

先发现并读取已安装的 `dimensional-drawing/SKILL.md`（本机路径通常为 `~/.codex/skills/dimensional-drawing/SKILL.md`），按其规则作图，不在本 skill 复制另一份绘图实现。技能不可用时明确说明，不把普通线框图冒称为该技能产物。

每个有独立结构的页面类型各画一张；同一类型的宽/窄屏、标签布局等变体可放在同张。无需为每条 CRUD 路由重复绘制相同结构。黑白图仅表达结构，不替代真实 Forge 视觉稿。

- 画区域与槽位：外壳、页头、标题/状态/操作、分组、标签/值或输入、说明/错误、关联数据、页脚；标注阅读顺序、FILL/FLEX/HUG 与滚动归属。
- 标出页面、卡片、字段、操作组分别拥有的 padding/gap，避免重复边距。宽表局部滚动；固定操作栏给内容留空间。
- 数值优先取当前 Core/Token、匹配的本地模板或实际测量。表中区分“源码现状”“公式推导”“设计提案”和 `[TBD]`；外部项目尺寸、截图比例、绘图坐标都不能直接成为 Forge 标准。
- 通用表单的阅读宽度、标签宽、组/字段间距和多列阈值，要结合真实字段及展开侧栏后的可用宽度确定。可先用页面推荐标准的基础填写区640、分组阅读区960、字段16/组24等设计起点；明确标为推荐且允许有理由调整。两列判定按实际字段容器 C ≥ 2m + g（推荐起点 m=280、g=24），不把584当视口断点。既有960指导不是所有表单的固定上限；商品模板280px辅栏是另一场景事实，与推荐字段最小预算280没有继承关系。
- 图内变量代码必须能在表中查到，公式可复算，标注无遮挡；未查证尺寸保留 `[TBD]`，不填看似精确的数字。
- 说明加载、空值/无数据、错误、无权限，以及编辑/只读/提交反馈对布局的影响；不额外发明业务状态。

交付包含可直接打开的 HTML/SVG 图纸、变量/规则与待决策、参考来源和代表性截图。已有项目产物可在本仓 `docs/design/forge-design-spec-v0.1.md`、`docs/design/form-detail-layout-research-2026-10-28.md` 与 `public/design/forge-design-spec-v0.1.html` 查阅；这些是本仓示例，不是其他项目必须存在的依赖。

## 4. 从图纸实现到验证

明确的用户设计选择优先沿用。已获实现授权且决策足够时，继续用真实 Forge 组件实现；不因画了图而自动增加一次审批。仅设计任务则停留在设计交付范围。

实施前读取匹配 case/组件 API；用 `AppLayout` 管外壳，用现有组件组合业务布局。模板适用时保留其固定/比例栏、间距和断点；不适用时记录差异及业务理由，不能只因“最接近”就强行复制。按宿主项目要求检查代码，在浏览器核对真实长中文、窄屏、展开/折叠侧栏、字段错误、长内容与关键操作反馈。

范围内的设计交付应同时包含固定/伸缩/滚动归属、状态、按实际可用宽重排的规则、可执行推荐默认值、确实影响业务且无法合理推断的待决策，以及TBD的原因/影响/补决策触发。仅设计任务不强制实现整个系统、补齐组件全库测试或开展范围外的设备验证；推荐规则与代码事实分别标注。

分别记录图纸完成、页面实现、技术检查、实际浏览验证和用户验收；生成图纸或通过 typecheck 都不等于整页体验已通过。用户确认只适用于其看到的交付范围。
