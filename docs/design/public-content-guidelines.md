# 官网内容与组件展示规范

适用于 Forge 的文档、组件参考、组件案例，以及组件内置的提示、按钮、空状态和无障碍标签。组件与文档面向人阅读和使用，准确、清楚、易懂是验收条件。

## 页面职责

- 文档：帮助读者了解产品、完成接入、处理问题。安装说明按环境要求、安装依赖、配置样式、使用组件、验证结果、下一步组织。
- 组件参考：说明组件用途、使用方法、可选配置与参数。代码标识保持准确，正文使用中文。
- 组件案例：展示具体场景与操作流程。点击后有对应结果，并提供必要的失败、取消、重试与恢复路径。

三者可以互相链接，但不能让读者为了看一个正常案例而到处寻找，也不能用案例替代必要的参数说明。

## 组件与变体的展示

每个可独立使用的公共组件应有可发现的用法和案例。配套子组件可以在父组件中展示，但要标明用途及参数入口；上下文提供器、渲染辅助函数和样式工具不要求各自占一张业务案例卡。

具有独立视觉或交互意义的变体都应能实际体验。例如普通与长按确认、不同金融卡背景效果、静态与可编辑评分、不同内容切换方式。只有导入、代码字符串或不可达分支，不算完成展示。

颜色、尺寸、语言等配置优先在同一案例中切换；不穷举所有配置组合。筛去重复展示时，不得删掉不同能力。交互状态应通过自然操作到达，必要时用清楚标注的模拟入口。

## 文案

1. 标题说清“是什么”，简介说清“什么时候用”。操作按钮说明动作，结果提示说明已经发生什么及下一步。
2. 默认中文；内置文案应可切换语言或覆盖。业务数据、日期与数字格式、无障碍名称也要检查，不能只翻译标题。
3. 保留组件名、参数名、包名、代码和原始错误信息。首次出现的必要术语给简短中文解释，不把所有技术词机械翻译。
4. 避免内部口语、迁移记录、截图要求和未解释缩写进入公开介绍。“手搓、外壳、吃参数、门禁、复核 Case”等不用于面向用户的说明。
5. 不使用无法证明的“全部、100%、唯一、完全一致”等承诺。数量、默认值、导入路径和支持范围应与当前源码和发布版本一致。
6. 样例数据使用自然且前后一致的中文。图例对应数据，统计单位可比较，金额币种一致，状态与进度含义明确。
7. 示例中的真实外部效果要说明边界。登录、邮件、支付等本地演示明确标注，避免用户等待并未发生的结果；无需每张静态卡重复免责声明。

## 交互与文档入口

可点击的入口必须有作用：链接到达明确目的地，复制操作有成功和失败反馈，搜索有结果和空状态。未实现的功能不要伪装成可操作按钮。

键盘可以完成主要操作。展开状态与内容一致，关闭后合理返回焦点；成功或错误可被辅助工具获知。懒加载示例不得在出现时抢夺用户焦点。

## 发布前验收记录

分别记录组件覆盖、变体覆盖、文案核对和真实操作验证。静态分析、代码测试、浏览器抽查不能互相替代。未确认的动态分支列为待验证，不把“源码引用过”写成“用户已经能看到”。
