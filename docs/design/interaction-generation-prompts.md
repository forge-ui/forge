# Forge 新交互动效生成提示词

参考目录：https://lucianlabs.dev/uxui-prompt

这是基于 Forge 现有代码的原创延展提示词，尚未实现新组件。参考站点的编号用于定位交互思路，不代表已经复用其代码或验证其线上动效。

## 统一基准：每次生成都附带

先阅读 core/src/internal/composer-quick-actions.tsx、core/src/internal/motion.tsx，以及本次需要复用的组件。保持 Forge 当前颜色、字号、圆角、间距和 Solar 图标。沿用 ChatInputBar 卡片隐藏在输入框后、选择后收拢成标签的空间关系；弹簧参考 composerMorph 的 visualDuration=0.42、bounce=0.16，按交互调整，不把所有过渡都套成同一个时长。沿用 LiquidTabs 的选中层、CalendarCard 的数字滚动和 AddMember 的对象移动思路。

使用 motion/react 和已有 CSS 过渡，不新增动画库。动效说明对象从哪里来、去哪里、状态为何变化。业务枚举状态使用文字，不新增彩色状态胶囊。已选智能体继续用头像和名字呈现；工具与 Skill 使用图标和名字。保持中文/英文文案可配置、键盘操作、焦点恢复和减少动态效果偏好。

真实状态和进度由 props、回调驱动，不用定时器伪造业务成功；计时器只能管理视觉过渡。提供受控状态和回调；关闭动效时保留状态和功能。中途取消、连续点击、失败重试、卸载清理均须正确。现有组件能扩展则先扩展，避免为同一交互复制一个组件。

先生成能交互的 showcase 原型，包含正常、处理中、失败、取消和无动效状态。不要发布 npm 或推送代码。确认交互后再确定是否进入 core。

## 1. 附件归位与上传队列

参考：075 Upload progress panel；051 Add-to-cart product card。

基于 ChatInputBar 的左侧加号和既有附件入口，设计上传文件归位动效。选中文件后，文件缩略片从选择入口短距离滑入输入框内附件区域；多文件按顺序归位，后续文件不覆盖已有文件。每个附件呈现名字、真实上传进度、取消或重试操作。完成时进度层收为完成图标，保留文件名；失败时保持位置，显示错误文字和重试。删除后相邻附件平滑补位。发送时将已完成附件 ID 提供给业务回调，上传中如何发送由明确 props 策略控制。

沿用标签入场和布局过渡；文件本体用折角、缩略图或页纹表达，不只放一个文件图标。拖入时可高亮投放区域，拖出恢复。无动效模式立即归位。不要伪造上传百分比或自动完成。

## 2. 工具调用卡：从标签展开，再收回结果

参考：080 Orbit sync spinner；086 Streaming AI answer。

基于 ChatInputBar 已选 Skill/工具标签和 Agent 运行组件，设计工具调用卡。点击发送后，将输入框内所选工具的视觉身份延续到消息流中：相同图标、名字和颜色关系。消息卡从紧凑工具行展开，依次呈现调用参数、运行步骤、结果摘要；多个工具有独立状态。运行时仅在当前步骤旁显示低幅度脉冲或小范围轨迹，不让整张卡循环跳动。完成后运行指示收成完成符号，详细步骤可折叠，摘要保留；失败时停在失败步骤，提供重试和详情。

消息区和输入区距离可能很远，不强制做全屏飞行；使用短距离展开或共享视觉元素维持连续感。停止生成后立即停止运行装饰，保留已产生的结果。真实状态由调用方传入，组件不能自行启动工具。

## 3. 批量选中操作台

参考：178 Bulk selection dock。

扩展现有表格选择和底部操作区域。未选择时操作台隐藏；第一次选择后，底部操作台由轻微上移和淡入出现，后续选择只更新数量，不反复播放入场。数量变化借用 CalendarCard 的数字滚动，只动发生变化的位。取消全部选择后收回；执行归档时表格中的已选行淡出并补位，在业务成功回调后显示可撤销通知。

操作台显示数量、取消选择、归档等传入动作。处理中防止重复提交，但不阻止无关页面操作。失败保留选择和行数据。支持快捷键和可访问状态播报。不得由动效直接删除数据，也不得用夸张飞行影响密集表格阅读。

## 4. Agent 变更审核卡

参考：127 Change hunk review；180 Approval sign-off line。

扩展 AgentDiffTable / ApprovalCard，让接受或拒绝一段变更具有明确反馈。展示原内容与建议内容，接受后被移除内容短暂淡出，保留内容平滑补位；拒绝后建议内容淡出，原内容保留。确认符号只在业务回调成功后出现。处理中显示等待状态；失败时恢复可操作状态并显示错误文字；撤销由业务方提供，恢复此前版本。

多段变更独立处理，不能因动画延迟导致接受错误段落。长代码保持滚动位置，不对整段文字逐字动画。键盘可定位到下一条待审核变更。文字状态优先，不用印章替代审批结果。组件只表达决策，不替用户自动批准。

## 5. 智能体协作席位

参考：131 Collaborator input cluster；196 Collaborative control handoff。

复用 AddMember 的头像移动和 ChatInputBar 的 agent 头像标签，设计协作席位原型。添加智能体后，头像从候选项归位到协作区，姓名始终可见；当前负责智能体周围有轻微选中层。切换负责对象时，选中层像 LiquidTabs 一样移动，原对象自然降为待命，新对象获得焦点标识。退出协作时头像淡出，余下席位补位。

成员、负责对象、添加/移除和移交均由受控数据驱动。切换动画不能自动移交权限或启动任务；业务确认失败时保持原负责对象。超过可见容量时提供明确的展开入口，不能仅靠头像让用户猜身份。减少动态效果时直接切换，不丢失姓名和状态。

## 6. 可恢复的搜索空态

参考：088 Empty folder that swallows paper；092 Empty search that loosens filters。

扩展现有空态和筛选区域。无结果时，以小型文件夹或资料页插画表达空状态，并根据业务方传入的建议显示“清除时间限制”“移除类型筛选”等操作。悬停建议时相关筛选获得轻微强调；点击后调用业务回调，待数据更新后空态收拢，真实结果以短距离淡入出现。首次加载、筛选无结果、错误和真正无数据须分别表达。

不要自动移除筛选，不要模拟结果数量。插画用现有颜色和 Solar 图形或简单原创 SVG；不增加持续漂浮、自动循环的装饰。用户返回空结果时能自然逆向恢复。

## 优先次序与验收

第一批：附件上传队列、工具调用卡、批量操作台。它们与当前聊天和 Agent 工作流的结合最直接。第二批：变更审核、协作席位、可恢复空态。

每个原型验收：真实数据回调、停止/取消、失败重试、连续操作、移动端换行、中文/英文、键盘、减少动态效果、无布局跳动。只有原型通过验收再进入正式 API 和 npm 发布流程。
