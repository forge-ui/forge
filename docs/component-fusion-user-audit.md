# 组件融合：普通用户体验修复与复审

日期：2026-10-15。本轮在本地开发分支修复并验证，不提交、不推送、不发布。

## 结论与边界

在本轮重点操作路径中，未发现尚未修复的阻塞问题。案例现在更清楚地说明操作目的、当前状态和下一步；按钮、附件、审批、预览和分派的文案与实际结果一致。

两位审计者分别按 55 项操作/表单和 44 项智能体/图表/组合清单核对实现归属与源码，并对高风险路径实测；第三位独立审计者复查修复代码，又发现审批跳过、成功焦点及验证码提示阅读时间三个问题，均已修复。源码清单覆盖不等于 99 项全部状态在本轮重新逐一浏览器验收。上一轮 103 项主路径记录见 [浏览器测试记录](component-fusion-browser-test.md)。本轮未完成全尺寸、触屏、屏幕阅读器及逐帧原版一致性验收。

## 已完成修复

| 场景 | 修复后的行为 |
| --- | --- |
| 验证码 | 父组件刷新不再不断延后清空；完整错误动画后清空，不抢回焦点；减少动效也保留至少 1.4 秒阅读时间；较新的输入不被旧请求清空。 |
| 减少动效 | npm core 样式覆盖子元素伪元素，关闭动效或系统减少动效时，书签等装饰不再遗漏。使用仅加载 core 样式的临时消费者页面验证，临时页面已移除。 |
| 附件输入 | 业务用 hasAttachments 确认附件就绪后，允许无文字发送；上传锁定、禁用和生成状态继续生效。实际发送后队列清空并显示附件数量。 |
| 审批 | 快速改选不跳题；明确继续/提交；返回保留答案，跳过删除本题答案；末题明确“跳过并提交”；提交载荷包含最后答案，防重复提交，成功状态承接焦点。 |
| 项目按钮与内容卡 | 创建后可打开实际项目预览并返回；文章预览只由按钮开关，避免 hover/focus 与点击反转，折叠内容对辅助工具隐藏。 |
| 表单与登录 | 懒挂载不抢焦点，用户切换步骤后才聚焦；修改邮箱可重新提交；明确第三方登录与邮件是本地演示。 |
| 智能体案例 | 7 类内置标签默认中文、支持英文及已有覆盖参数；建议接受/备选、洞察追问、命令选择都有就地反馈。银行卡片补齐语言标签，修正案例将完整卡号错误传给尾号参数的问题。 |
| 工作分派 | 独立显示总分派进度与待分派任务；九项任务明确，完成反馈包含任务名和成员，不再把全局比例解释成下一任务进度。 |
| 累计图 | 三类数据统一为项目存储，清楚定义 GB·h，避免把接口、模型和存储直接累加。 |
| 案例排版 | 卡片保留 18 种代表业务案例；按钮整理成 5 组常见场景，删除重复主题/尺寸参数矩阵，补齐图标名称、操作反馈和编辑结束后的焦点返回。融合案例仍完整展示在对应分类页。 |
