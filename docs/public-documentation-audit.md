# 官网文档与公共操作审计

日期：2026-10-15。审计对象为 `/docs` 全部 6 个内容页、导航、目录、代码复制、公开 AGENTS.md 内容及共享网站顶栏。仅新增审计材料，未修改页面。

## 判断标准

以第一次使用 Forge 的开发者为读者：先说明用途与适用场景，再给可执行步骤和示例，最后说明配置、限制与下一步。页面正文使用正规、自然的中文；组件名、参数名、包名、错误原文保留准确标识。技术术语首次出现时解释，不把内部开发要求当作产品介绍。

参考 [HeroUI 介绍](https://heroui.com/cn/docs/react/getting-started)、[快速入门](https://heroui.com/cn/docs/react/getting-started/quick-start)、[组件目录](https://heroui.com/cn/docs/react/components) 的信息分层：介绍、安装、使用、下一步与组件分类分别承担职责。以下标准和替换方案是针对 Forge 的审计建议，不代表复制参考站内容或直接采用其能力承诺。

## 仍需验证的内容，不能直接称为已坏

- `agents-md/page.tsx:22` 的 https://forge.ui/agents-md 与安装脚本使用的 forgeui.org 域名不同；本仓未见该下载路由或重写。必须验证部署端的响应与内容，不能仅据本仓缺路由断言远程服务不可用。
- Skill 在不同 AI 助手中的安装目录、自动发现和 /forge 调用规则需要按工具版本验证；本轮只审查源码声明，没有运行安装脚本或更改用户配置。
- 外部依赖、图标授权等信息应放在依赖或授权说明中；本轮未执行法律审查，不改写其许可证结论。
- 介绍页“每个组件都有 API 表”的承诺需要与完整导出覆盖报告交叉核对，不能用少数页面推断全库。

## 共享入口与组件内置文案补充

- 官网顶部搜索和页内反馈属于共享入口，问题不只影响入门页；组件参考、案例目录同样需核对 `_toc.tsx` 的 `href="#"` 反馈入口。
- `src/app/templates/page.tsx:46–69,89` 的目录标题仍为 Examples，Micellaneous 保留拼写错误，说明中出现“保留原目录拼写”“原始截图”“配色齐活”“外壳”等内部或口语表述。建议使用“业务模板”，按实际用途命名与介绍，例如“客户管理”“电商管理”“后台布局”。本轮包含模板索引，不包含全部业务模板内部页面。
- `src/app/layout.tsx:11` 的默认标题为 SaaS Starter Kit，应核对官网产品定位并改为准确的站点名称；不是把代码中的产品名一律译成中文。
- `core/src/components/ui/chat-input-bar.tsx:80` 的默认模型菜单名称仍为 Model；该值用于菜单与可访问名称。其 locale 未覆盖所有内置标签。应集中定义默认中文与英文，保留业务方参数覆盖能力。
- FullCalendar、SmallCalendar、SmallDailyCalendar 的固定中文控件未提供完整语言切换能力。FullCalendar 在周/日视图仍读为“上个月/下个月”（:131、:133）；应随视图标注为上一周/天、下一周/天。
- FullCalendar 详情中的“编辑日程”“更多操作”（:230–231）没有处理函数，也没有对应业务回调参数；应提供可接入能力，未配置时隐藏操作。
- 其他内置文案详见 [组件参考审计](./component-public-copy-audit.md) 的补充章节：包括表格选择与排序、侧栏消息和通知面板，以及若干选择器。已有手动标签覆盖与真正随 locale 切换必须分别记录，不能混为一谈。
