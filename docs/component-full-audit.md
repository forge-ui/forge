# 组件、案例与官网文档全面审计

日期：2026-10-15。对象：当前开发分支的本地内容。

## 结论

当前不能认定“所有组件及有独立意义的变体均有完整案例，且官网已适合首次使用者”。问题包括真实展示缺口、文档与实现不一致、示例场景不完整、内置语言切换遗漏，以及没有实际功能的公共入口。已形成逐页和逐组件清单，本轮没有修改产品实现、提交或发布。

审计始终采用同一标准：组件与官网服务于实际使用者。标题说明用途，描述解释行为，案例呈现可信的业务场景；代码标识保持准确，中文解释正规、简洁、易懂。该标准已写入 [公开内容规范](./design/public-content-guidelines.md)。

## 范围与证据

| 范围 | 本轮工作 | 判断边界 |
| --- | --- | --- |
| 公共组件 | 从 core 真实入口识别 182 个 React 导出，区分 138 个用户组件、26 个组合子组件、16 个渲染辅助和 2 个上下文辅助；提取 469 个有限属性轴 | 属性轴不是需要新增的案例数量。排除通用 HTML 透传项，不要求颜色、尺寸和状态的所有组合逐个铺开 |
| 组件参考 | 30 个 page 文件，含 27 个正文页及 3 个入口或跳转；核对说明、参数、默认值和链接 | 逐页源码审查，不等于每个状态均通过浏览器验收 |
| 组件案例 | 全部案例页源码与共享注入内容；27 个主要分类页的浏览器页面检查 | 页面检查与主要路径操作不能替代每个变体、异步和键盘流程验收，详细范围见案例报告 |
| 使用文档 | 6 个内容页、共享导航和复制区、公开 AGENTS.md 内容；实际操作介绍与快速开始页面 | 未执行所有外链验证、全新项目安装和全部辅助技术测试 |
| 其他入口 | 官网共享导航、模板索引、默认站点标题 | 不包括所有业务模板内部页面及其后端功能 |

覆盖脚本只统计真实 JSX，不把 import、注释、代码字符串当成展示。共享调用关系只能证明静态可达候选，不能计算实际可见覆盖率。没有独立案例也不等于每个辅助组件都应新增案例。

## 优先修复清单

### 第一批：让读者能够正确接入

1. **修复样式扫描路径说明。** 快速开始与安装页写 app/globals.css，却固定使用适用于 src/app 的相对路径。分别给出两种项目目录的正确配置，并在独立项目中编译验证。
2. **修复不存在的导入路径。** 公开 AI 规则提供 `@forge-ui-official/core/app-layout`，但包没有导出此路径。所有可复制的代码应通过实际包入口编译检查。
3. **校正文档中的事实错误。** 搜索框被写成不支持 onChange；多个默认值仍是旧英文；图标容器尺寸说明矛盾；出现不存在的 body 参数；长按按钮的样式说明遗漏。参数说明应与当前类型和实现逐项对齐。

这些问题应优先于措辞润色。P1 指阻碍接入或使用户按文档操作失败，不代表安全漏洞。

### 第二批：补齐有意义的展示与操作

- 未找到 ImageGrid、ProductRow 的案例 JSX；需补真实业务展示或说明其组合位置。CalendarWeekRow、CellProgressValue 属于组合能力，应在相关案例中解释，不机械增加独立展示卡。
- DebitCard 仅见 glow，缺 flat、gradient；IconButton 未见核心 send effect 的实际展示。优先在现有案例增加变体选择，不恢复尺寸、颜色矩阵。Button 四种 effect、IconButton 两种形状、TabsContent 的 slide/fade 已有 JSX 证据，不重复补卡。
- 日历详情里的编辑、更多操作没有处理函数与对应业务回调；应提供可配置操作，未配置时隐藏。
- 聊天案例应在发送后显示消息或明确反馈；不能让使用者看到输入消失，却不知道是否发送成功。
- 恢复卡片中有独立意义的装饰、无标题和头像回退展示，合并完全相同的列表批量操作案例；用切换控件组织，不恢复铺满页面的重复矩阵。
- 非删除弹窗不能复用“删除后无法恢复”；图表分段、图例、币种和指标口径必须一致。

### 第三批：统一中文、语言切换与公共表述

- ChatInputBar 默认模型菜单名称仍为 Model；部分组件 locale 只覆盖局部标签。
- 表格选择、排序与统计，侧栏通知和消息面板，以及部分选择器、日历仍有固定语言；手动传入标签与自动随语言切换必须分开说明。
- 日历上一步、下一步的可访问名称应随月、周、日视图变化。
- 删除公开页面里的复核记录、Figma 文件说明、原目录拼写解释、“手搓”“外壳”“配色齐活”等内部或口语表达。保留组件名、参数名、类型和错误原文，不作机械翻译。
- 删除没有证据的“所有”“100%”“靠谱十倍”等承诺；示例中的姓名、任务、金额、状态应自然且自洽。

### 第四批：修正网站入口与阅读顺序

- “组件示例”实际指向介绍页；应区分“组件参考”和“组件案例”，各自链接到正确位置。
- “复制页面”、顶部搜索、反馈入口目前存在未实现或仅指向 # 的情况；提供真实功能，未实现时移除入口。
- 复制命令、代码、规则应使用各自准确名称，并提供成功与失败反馈。
- 更新案例索引、旧版安装示例和模板目录名称；检查站点默认标题是否准确。
- 每页先说明用途，再展示主要用法；相关示例就地展示，使用选择器组织有独立意义的变体，不要求用户到另一个总目录寻找。

## 修复后的验收标准

1. 首次访问者能从导航找到组件用途、示例与参数，标题和描述不依赖内部背景。
2. 公共用户组件及有独立意义的变体有明确展示位置；组合子组件通过组合案例说明，辅助组件不凑数。
3. 默认中文；切换语言后可见标签、提示、错误、状态、菜单与可访问名称同步变化。业务数据不应由组件擅自翻译。
4. 每个展示为可操作的入口均有结果；演示无需真实后端，但本地行为和反馈应完整。
5. 示例数据、图例、单位、指标口径一致；数量、尺寸与排版支持阅读，不重复堆放矩阵。
6. 可复制安装命令、样式与代码在实际消费者中通过；参数表与类型、默认值一致。
7. 浏览器验收单列：初始、悬停、焦点、禁用、加载、错误、完成、关闭、重置，以及移动布局和减少动态效果偏好。源码审计通过不能替代这些验证。
