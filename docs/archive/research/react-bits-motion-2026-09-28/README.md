## 4. 当前源码对接点

1. `Button` 目前是原生按钮包装，尚无专门 loading/success 状态接口；`IconButton` 已有颜色 transition。第一批先补基础视觉反馈，新增状态 API 需独立设计。
2. `DropdownPanel` 是无 open 属性的外观容器。`KebabMenu` 通过 `open && createPortal(...)` 挂载；`SelectOption`、`Tooltip` 同样条件渲染。退出动画应由拥有开关状态的控制层管理，关闭时先进入退出阶段再卸载，快速重开必须能取消退出。
3. `SelectOption` 通过切换上下箭头组件表示展开。连续旋转需稳定同一图标节点，并尊重弹层方向和减少动态效果设置。
4. `SidebarMenu` 与 AppLayout 内部侧栏都有独立子菜单展开路径，不能只改其中一个。已有箭头过渡可保留；当前子项条件挂载需要配合高度过渡调整。
5. `TabBar` 只在选中项内部渲染下划线，缺少跨选项移动的同一个指示器。需处理标签变宽、容器 resize、滚动及键盘选择。
6. `Toggle` 当前通过 `justify-start/end` 切换滑块端点，已有颜色 transition 不会自动产生位置过渡。需要稳定滑块并动画化 transform。
7. `Checklist` 已有填充、勾线、划线、完成反馈以及减少动态效果分支。先统一已有实现，避免另建一套 Spring Check。
8. `RatingStars` 是只读评分展示；`Stepper` 是无文字的点条指示器；`ConfirmationDialog` 是确认内容面板。它们分别不同于交互评分、完整分步表单和管理遮罩/焦点/Portal 的完整对话框。
9. Agent 家族已有 `forge-shimmer`、`forge-fade-up`、`forge-stream-in`、`forge-pulse-dot`，以及部分 reduced-motion 规则。动效规范应覆盖并收敛这些已有定义。

## 5. 实现建议与复用边界

- 先建立 motion token：快速反馈约 100–140ms、普通开合约 160–220ms、内容切换约 220–280ms，初始位移建议 2–6px。这些是待视觉验收的 Forge 建议值，不是现成 token 或上游必须参数。
- 基础交互优先使用 CSS transition / keyframes；测量位置、退出延迟和 tooltip 延迟组使用少量 React 状态。只有需要复杂手势或共享布局弹簧时，再评估 Motion 单独依赖。
- 上游 Glide Select、Branched Menu 等无需 Motion 的版本也能实现主要效果；Specular Button 则依赖 OGL。不要为了所有按钮的轻微按压引入 WebGL。
- 上游部分组件使用 Hugeicons、React Icons、Lucide 或 react-router-dom；Forge 适配应沿用当前图标入口和路由机制，不因参考动效增加平行体系。当前合并中的图标迁移应以源码为准。
- 视觉时间不控制真实业务完成状态。关闭期间不可继续点击隐藏选项；关闭后的焦点返回、快速连续开关、Esc、滚动定位、受控值、禁用、SSR 首帧和 reduced-motion 都属于实现验收范围。
- reduced-motion 下直接切换终态或保留极短淡化，去掉弹簧、位移、拖尾和循环。装饰循环在离屏或终态停止。
- 简单按钮仍可保持无额外客户端状态的实现；不要为了统一动效把全部 core 包装成一个全局客户端动画容器。

**源码复用边界：** 当前上游许可证为 MIT + Commons Clause，并明确限制重新分发组件本身，包括打包或移植。Forge core 是发布组件的 npm 包，不能把上游视为普通 MIT 直接复制发行。这里的表格是效果与功能映射，不构成源码接入授权。建议在 Forge 原有组件上依据行为需求独立实现通用交互；如果要复用具体上游代码，则需先确认覆盖组件再分发的授权。单改名字、颜色或图标不等于独立实现。[上游许可证](https://github.com/DavidHDev/react-bits/blob/a0c0548a28fa951a8f5c605d28b2480234bc72e4/LICENSE.md)
