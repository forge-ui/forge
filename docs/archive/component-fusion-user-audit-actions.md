## 需处理的问题

### P2：创建后的“打开项目”仍执行反向切换

位置：`src/app/components/_fusion/actions-buttons.tsx:69`。

002 的 onClick 始终 `setCreated(value => !value)`。首次点击创建后显示“打开项目”，再次点击会回到“创建项目”，而不是进入项目。普通用户无法根据按钮文字预测结果。虽然是演示，也应该提供一致的动作结果。

建议：创建完成后提供一个明确的本地项目预览，或保持创建完成状态；用单独的“重置”恢复演示，避免让“打开”承担撤销创建的功能。此项为源码确认，浏览器第二步未可靠复现。

### P2：阅读预览自动展开与点击切换互相冲突

位置：`src/app/components/_fusion/actions-cards.tsx:12–14`。

049 hover 或 focus 会 setOpen(true)，同一区域内按钮点击又 setOpen(!open)。用户把鼠标移向“阅读预览”时会先展开，然后首次点击立刻关闭；键盘 focus 后按 Enter 同样可能关闭刚出现的内容。缺少 onBlurCapture 还会使键盘离开后持续展开。

建议：让预览按钮成为明确的开关；hover 只做抬升/层次反馈。若保留 hover 预览，用独立 hover/focus 状态决定展示，显式按钮控制 pin 状态，不共用一次反转。

### P2：多示例页面中的向导初次挂载会主动夺取焦点

位置：`src/app/components/_fusion/forms-navigation-menus.tsx:105`，`src/app/components/_fusion/forms-navigation-forms.tsx:208`；懒加载关联 `src/app/components/_fusion/family-examples.tsx:17–19`。

042 和 063 都在 step=0 首次挂载时执行 input.focus()，而案例有 300px rootMargin 的懒挂载。普通读者滚动浏览其他案例时，刚接近视口的表单就可能夺走焦点、滚动画面或在移动端唤起键盘。实测直接进入 042 后在未点击输入框时 activeElement 已为该姓名 input；普通滚动具体跳动尚未独立复现。

建议：首次挂载不主动 focus；仅用户明确点击下一步/上一步后将焦点送往新步骤。使用 preventScroll，并等待 slide 面板真正进入后聚焦，避免 ref 仍指向旧输入。

### P2：社交邮箱演示请求后可改地址，却无法再提交

位置：`src/app/components/_fusion/actions-buttons.tsx:161–163`。

提交后 state=sent 时禁用按钮，但邮箱输入仍可编辑，onChange 只 setEmail。用户发现地址填错后修改地址，按钮仍禁用；状态文案还会随新地址变成“请查看收件箱：新地址”，即使新地址从未提交。建议保存 requestedEmail 并显示该地址；编辑时清除 sent 状态，或提交后锁定输入并提供“更换邮箱”。此项源码确认。

### 明确体验缺陷：社交登录的演示边界不清楚

位置同上 `:149, :161–163`。该流程纯本地状态，却使用“账号已连接”“请查看收件箱”等真实完成措辞，没有像 062 的“本地交互演示，不会发送登录信息”说明。普通用户可能去真实邮箱等待邮件。建议在整个社交登录卡片底部添加简短的演示说明，并把结果改为“登录链接请求演示完成”。这是案例表达问题，不是要求组件接入真实认证。

## 保持与建议

- 004、026、062 已有清楚的忙碌/失败/取消或重试反馈，不需要为了“更像业务”增加后端。
- 验证码的“返回验证成功/失败”是开发者驱动状态控制，已有说明；不作为普通用户真实登录按钮去否定它，可在视觉上与输入区分开。
- 090 自动重试默认约 15.4 秒可恢复且提供立即重试，不是功能错误；普通浏览时可考虑默认等待用户启动，避免读到时动画已经结束。属于可选建议。
- 对齐原版不等于保留所有装饰；优先让标签、结果、取消和再次操作具有一致含义。

### 最终结论

本轮修改涉及的关键操作，文案与结果一致，有明确本地演示边界；已检查的流程可继续操作或返回，不再将旧问题列为未修复。按钮页从参数穷举变为五组业务动作，主要按钮、图标按钮、文字链接三种组件均保留，纯图标入口有名称；FamilyInteractionDemos 和验证示例继续由 layout 注入。
