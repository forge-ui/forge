# 组件案例全量审计（2026-10-15）

## 范围和方法

只读检查当前工作树的 `src/app/cases` 全部 27 个主分类页面、3 个入口/子路由、共享布局，以及布局追加的 `FamilyInteractionDemos` 和 `FusionFamilyExamples`。使用现有 Chrome 独立标签逐页加载 `http://localhost:3001/cases/<分类>`，读取实际 article 的标题、说明、可见文字和按钮；结合源码确认数据、回调和变体。未启动新浏览器进程，未改正式组件、未提交。

这是全页面内容与结构审计，**不是每个按钮、每个视口和每帧动画的全量 E2E 验证**。下面明确区分代码可确认的功能问题、明确内容/体验缺陷与整理建议。源码行号以本轮工作树为准。API 名如 ChatInputBar、size、locale 可以保留，不要求把代码标识翻译成中文。

## 优先修复的问题

### P1：案例里输入后发送会清空，但没有结果

位置：`src/app/cases/chat-input-bar/page.tsx:27-30,41,48,54-60`；组件行为见 `core/src/components/ui/chat-input-bar.tsx:343-347`。

暗色窄容器及复用的 prompt 没有 `onSend`。自定义 AskAi composer 也复用该 prompt，外层 AskAi 的 onSend 不会自动接管自定义输入框。输入文字点击发送时，组件可清空文字，但本地消息、生成结果、错误均不出现。顶部快捷卡片示例和生成/停止示例已接通，不能据此认为全页都可完成发送。

建议：各场景接本地消息回显或共享演示会话；将模型/权限信息换成用户能理解的已选值。回调次数、`read/auto`、附件点击数移入技术说明。不要接真实后端以完成展示。

### P2：确认弹窗四种操作使用了删除警告

位置：`src/app/cases/modal/page.tsx:35-65`。

“发送确认消息”“保存修改”“升级专业版”“激活账号”均写“删除后无法恢复”。后果与按钮不匹配，会让人误判操作。第 79-95 行的内联弹窗没有事件反馈，点击确认/取消也没有演示结果。

建议：每个业务动作明确对象、后果和成功反馈；颜色、按钮对齐方式用控制切换。下方布局注入的真实弹窗/抽屉已经能开关，保留并作为主要体验，不应只留下静态矩阵。

### P2：多个图表的标题、数值、图例不构成同一件事

位置：`src/app/cases/chart/page.tsx:99-174`。

分段条有 50/30/20 三段，图例只有两个渠道，金额 20,000/40,000 又不对应比例；同卡“今日增加 ¥181”和“你已获得 $240”混用币种。半环及虚线半环说明是目标完成率，却仍命名“本月收入分布”，没有目标金额，图例渠道金额也不能解释 75%。这不是要求所有金额人民币，而是要求一张图的口径自洽。

建议：占比图采用三个有名称且金额相加一致的渠道；完成率图显示“已完成/目标”及周期，统一币种。已精简的五段饼图和四层项目进度图不需要恢复 1—5 段矩阵。

### P2：换汇案例既无换算结果，也有货币矛盾

位置：`src/app/cases/other-widget/page.tsx:11-26`；默认值 `core/src/components/ui/currency-converter.tsx:92-109`。

案例只传视觉 props，无 onConvert、金额或币种选择回调；两端默认 USD，提示却是 EUR/USD。输入后点“换算”、币种下拉及更多按钮没有业务结果。页首还承诺“星级评分、图片排列和产品条目”，页面实际只有换汇。

建议：用固定演示汇率接通 EUR→USD 的金额计算/切换，并明确“演示汇率”；页面承诺与实际内容一致。若这些组件已有其他归属，链接到对应分类，不为凑说明再复制一套。

### P2：聊天页面公开了内部复核说明，变体数量也不一致

位置：`src/app/cases/chat/page.tsx:599-621,717-720`。

标题“Chat 复核 Case”、Figma 文件名 chat.md、Purple 一行 5 种 panel 都是制作过程说明。实际全页面只有 Variant 1、2、4、5 四项，缺 3。不能仅改“5”为“4”就断言缺失功能已解决：应先确认缺失的第三个布局原来是否有独立用户用途，再决定补回或合并说明。

建议：改成“私聊与联系人资料”“团队聊天与成员管理”等场景名称，说明用户要完成的操作。API 名另列即可。

### P2：卡片精简丢掉独立视觉/结构变体

对照 `git show HEAD:src/app/cases/card/page.tsx` 与当前文件：原第 110-115 行有无标题 SurfaceCard；原第 361-387 行金融卡同时展示 glow/orbs；原第 489-510 行用户卡有图片/initials 回退。当前第 61 行 DebitCard 固定 glow，第 64 行 CreditCard 固定 flat，第 80 行 UserCard 只有图片；没有对应控制器。

这些不是纯颜色重复。建议在现有业务卡片旁提供“装饰样式”“头像来源”“显示标题”切换，恢复可比较能力。**不要恢复八色银行卡、所有颜色尺寸铺开的旧矩阵。** 当前卡片页的业务叙事、余额隐藏和成员选择反馈明显更好，应保留。

### P2：列表批量操作出现同一个演示两次

`src/app/prototype/component-fusion/_catalog-data.json` 的 178、F03 均为 list 分类、kind=selection；`src/app/components/_migration-previews.tsx:55` 都渲染 SelectionToolbarPreview；注册表 `src/app/components/_fusion/registry.ts:7` 同时纳入二者，family-examples 第 48-50 行逐条渲染。

因此“批量选择操作台”和“列表批量操作”是同一流程的两次入口，没有独立差异。建议合并一个案例、保留映射关系；如果确需两个，应明确文件归档与另一业务流程的差异，不能只改标题。

### P2：默认英文和占位数据仍分散在基础案例

确认实例：地图 `src/app/cases/map/page.tsx:14-18` 的 340 Sales 等；输入 `src/app/cases/input-field/page.tsx:132,150` 的 Error message goes here；历史第 36 行 DD/MM/YY,00:00、第 97 行 Label；聊天、菜单、表格、工具栏仍有完整英文普通标题和 Figma 说明。

建议：业务文字默认中文，错误文案给出修正方法，例如“请输入有效邮箱”；时间用真实格式示例；业务数据给出具体对象。API 标识、货币代码、品牌名不属于必翻译项。共享 `_labels.ts` 只能翻译完全匹配的名称，无法覆盖“Text Field - States”“Circle Icon”等拼写和组合标题，不能作为全页中文的验收依据。

## 布局追加内容与入口

- `src/app/cases/layout.tsx:21-22` 顺序追加两层示例。新月历、成员选择、OTP、液态页签及所有融合示例都已归入原分类；没有单独新增“交互动效”导航的必要。
- `FamilyInteractionDemos` 的 motion 状态和 `FusionFamilyExamples` 的 locale/color/motion 是独立局部状态。当前同页可能出现两处动效/语言控制且互不影响，容易误以为主题失效。建议统一页面级设置，或明确标“仅作用于以下示例”。不是所有 locale 都必须支持同一语言格式字符串。
- `src/app/_components/animated-widget-demos.tsx:32,39` 的“蛋壳裂开”“无内部类覆盖”等是实现/测试语境，建议改成“验证失败后可重新输入”“紧凑日历用于表单日期选择”；保留演示固定验证码说明及添加失败演练，它们有助于完成流程。
- `src/app/components/_fusion/family-examples.tsx:52` 文案“浏览其他分类示例”链接 `/cases`；该入口直接重定向按钮与链接，不是分类目录。建议删除这个多余尾链，或改成准确目的并使用现有侧栏导航。不要重新增加用户已拒绝的“全部示例”。英文分支仍是 Browse all interaction examples，中文/英文意图也不一致。
- `/cases` 重定向按钮与链接；`/cases/motion` 使用 LegacyInteractionRedirect；`/cases/menu-sections/[view]` 重导出分组页。它们不是额外三组案例，不应在统计中重复计算。旧动效入口需要保留跳转定位而不是恢复旧分类。

## 收敛方式与验收建议

1. 先修错文案、数据口径、发送/换汇等无结果操作，再动排版。每个案例用一句话说明目标，示例数据围绕同一对象，动作反馈放操作附近。
2. 每个独立用户能力保留一个有业务内容的可完成场景；颜色、尺寸、背景、对齐用控制切换。恢复卡片独立模式，同时删除 list 完全重复的流程。
3. 中文默认验收应覆盖标题、普通说明、占位、错误、空态、成功状态和样例数据；API 字符串可保留。搜索 Figma/matrix/复核/原型/示例文本/英文错误只是线索，需要逐处判断，不做盲目全量替换。
4. 整理后实际点测：输入发送有回显；换汇有结果且币种一致；确认/取消后果准确；筛选可恢复；批量操作可撤销；日历视图/日期可切；卡片独立模式可见；语言与动效控制范围明确。随后检查窄屏和长内容，不以构建成功替代这些体验验收。
